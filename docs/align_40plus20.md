# 统一60轮预算：新结构40轮联合训练＋20轮局部训练

新版本 `projection_only_v1_v2_align_40plus20_v1`，仅新增AGIQA-3K、AIGCIQA2023两次下游运行。保留全部旧结果，不替换整体最好基线。1K不重跑，不增加RichHF热身，也不读取先前60轮成熟模型或局部20轮检查点。

## 研究问题与对照

同一份最好基线项目预训练权重（SHA256 `fa702194827ea2023375cef8dfec6014e9dd91fd80207a00ecebbb7ae6e34686`），相同train_seed=42、split_seed=42、数据划分、增强、损失与初始分组学习率：

- 原结构60轮：复用 `run_align_representation.py` 的 `aprobe`。
- 新结构60轮联合训练：复用该脚本的 `aregionword`。
- 新增路线：**同一个新结构**，第1—40轮联合训练，第41—60轮保护质量／全局路径，仅训练新区域/文本投影、局部一致性头和一致性门控。

三组都从原项目预训练检查点开始，**不加载旧下游成熟模型作为起点**。新投影采用与已有aregionword一致的随机初始化；不存在只在第41轮新建投影的额外因素。该设计主要比较“新结构全程联合训练”与“后20轮冻结”的差异。前40轮在合成CPU测试中参数、缓冲区和随机数状态完全相同；GPU执行不承诺逐位复现。

来源、旧配置快照、完成状态、权重来源指纹、初始优化器与60轮LR轨迹、实际数据成员先通过核验，已有60轮实验才可作为对照；不会自动重跑这两组。历史最好基线的两份CSV另列为参考，不能代替同批对照或混淆选模策略。

## 第40／41轮边界

第40轮结束后，直接保留**当前**模型继续训练，不回滚到前40轮的验证最优，不加载外部教师，不重置优化器、GradScaler或学习率调度器。

全程只有一个AdamW和 `CosineAnnealingLR(T_max=60, eta_min=1e-6)`。第41轮align组起始LR约2.575e-5，而不是重新从1e-4开始；局部Adam步数必须接上前40轮。原参数组仍保留，冻结参数的grad清空，不再更新；调度器继续记录全部组的LR。

冻结范围包括CLIP、ResNet、全局及P₀投影、PI/PT、文本上下文、AG/AT、全局一致性头、全部QA/QL/NSS/质量头及质量混合参数。冻结同时覆盖参数、BN运行统计与Dropout模式。后20轮唯一可训练模块为 `align_region_word`、`align_patch_head`、`align_gate`。

损失系数沿用原aregionword。冻结的质量损失仍可被记录，其梯度不再更新质量参数；不通过额外改权重引入第二个因素。训练到60轮后、恢复任何选中模型前，验证冻结参数与全部注册缓冲区（包括非持久归一化缓冲区）的SHA摘要一致。第41—60轮验证质量和全局一致性指标与第40轮相比绝对差不超过1e-6。此证明针对训练末状态；若最终选模选中第40轮以前的模型，其指标当然可以不同。

`fair_phase_manifest.json` 记录边界、冻结摘要、实际可训练参数、边界前后Adam步数和LR连续性。每轮CSV记录实际处理批次、成功更新和AMP跳过次数，不能仅因“60轮”就宣称FLOPs、耗时或有效更新次数完全相同。

## 选模与测试

严格沿用已有两组对照的一次60轮轨迹、两种验证选模：

1. **Q策略**：最大验证 Quality SROCC，作为与原Quality选模规则相符的主比较。
2. **J策略**：最大验证 `(Quality SROCC + Align SROCC)/2`，作为预先定义的第二套完整对比。

两种策略都在全部1—60轮中选模，并列保留最早轮次；第41轮不重置候选集合，不强制选局部阶段。Q策略可能选中前40轮，这属于该选模规则的结果。只在60轮训练全部结束后评估选中模型的验证和测试，同一轮被两种策略选中时仅评估一次。第40轮使用原本的逐轮验证结果，不额外验证或测试。报告时按相同策略比较三组，不能把一组Q策略和另一组J策略的最高测试值拼成公平对照。

## 服务器执行

先检查并保留工作区改动，然后同步：

```bash
git status --short
git pull --ff-only origin work
```

只检查新配置，不读取大权重或训练：

```bash
bash scripts/run_align_40plus20.sh all --dry-run
```

核验实际来源和已有对照、并检查新目录状态，不启动训练：

```bash
/home/sll/anaconda3/envs/WZX-AI/bin/python scripts/run_align_40plus20.py check-inputs
```

**两卡各运行一个数据集，nohup+setsid后台启动：**

```bash
bash scripts/launch_align_40plus20_background.sh
```

只会启动两次新增40＋20轮任务：GPU0跑3K，GPU1跑2023。打印PID和唯一日志目录，可按打印的tail命令查看。CPU真实训练会被拒绝。不要重复启动同一任务；旧的 `restart_protected_local_background.sh` 专用于先前protected_local实验，不用于本版本。

单卡顺序执行：

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_align_40plus20.sh all --continue
```

也可单独指定 `a40local20 agiqa3k` 或 `a40local20 aigciqa2023`。`--continue`只核验并跳过完整任务，不恢复半轮、不覆盖半成品。模型仍在内存中选模；本路线不从旧20轮检查点延长，不保存用于中途恢复的优化器/RNG状态。服务器重启或训练被杀后的部分目录须先保留再核查，不能声称已经恢复原轨迹。

梯度诊断仍按原对照采样第1、10、30、60轮各两个批次。第60轮共享路径已冻结，`no_trainable_parameters`是预期状态，不应当伪造为零梯度或当作训练失败。非有限诊断保留原记录，不能作为梯度冲突证据。

两次新增任务都完成后：

```bash
bash scripts/run_align_40plus20.sh pack
```

输出 `projection_only_v1_v2_align_40plus20_v1_results.tar.gz`：包含两次新运行、原模型60轮与新结构60轮的四次已有对照，以及两份历史参考CSV（共8份CSV）、各自配置／日志／元数据／来源指纹、冻结证明、划分和统一比较协议。不会包含大权重，不把旧80轮实验或RichHF热身成绩混入本次60轮对照。
